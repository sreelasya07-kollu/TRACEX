# Conventions

## Git workflow
- Commit only when the owner asks (HANDOFF.md §1). Agents never push.
- `main` is the default branch. Branch protection ("Require PR", code-owner review, the
  "Charter integrity" check) is an owner step, tracked in [04-TASKS](04-TASKS.md); until it
  is set, the charter hash check is tamper-evident only (see `.github/CODEOWNERS`).
- Commit messages: conventional style, as in `git log`: `feat(scope): ...`, `fix(scope): ...`,
  `docs: ...`, `test: ...`. Add the task ID when there is one: `feat(qa): T-NNN add ...`.
- PRs use [.github/pull_request_template.md](../.github/pull_request_template.md) (task ID,
  phase, checklist).

## Agent workflow (planner -> coder -> reviewer)
- Every planner brief names its task ID (`T-NNN`) from [04-TASKS](04-TASKS.md).
- On brief OK the main session moves the task to IN PROGRESS (owner, date). At commit it
  moves it to DONE with the commit hash. Nobody else edits task status.
- New work found during a task becomes a new TODO row; it is not silently built.
- Doc updates outside the task's own files (01-TECH-STACK, 02-ARCHITECTURE, 05-CONVENTIONS,
  the handoff) happen only in `/end-session`.
- A brief that adds, removes or re-pins a dependency includes an ADR step
  ([decisions/](decisions/)).
- Scope: the charter plus approved amendments ([README](README.md)). Anything else goes to
  `docs/change-requests/` first.

## Multi-person / multi-session rules
- Never work on a task someone else has claimed.
- Don't refactor files outside your task's scope.
- Handoff notes go in NEW files in [handoff/](handoff/); never edit an existing one.

## Code style
- Linter / formatter: ruff; rules and line length in `pyproject.toml` (`[tool.ruff]`).
  Run `uv run ruff check` before commit.
- Layout: one top-level package per module (`formats`, `spatial`, `recon`, `router`, `qa`,
  `export`, `eval`); boundaries per [02-ARCHITECTURE](02-ARCHITECTURE.md#module-boundary-test).
- Formats: change the pydantic model in `formats/`, regenerate `spec/` with
  `python scripts/export_schemas.py`, update [INTERFACES.md](INTERFACES.md), bump the format
  version per INTERFACES.md semver rule.
- Units and frames: [INTERFACES.md §0](INTERFACES.md).

## Tests
- pytest, files in `tests/`. Every test carries a resource marker defined in
  `pyproject.toml` (`light`, `heavy`, `gpu`, ...). `uv run pytest -m light` is the fast gate.
- Each test checks a measured quantity against a threshold; no piles of mock tests
  (HANDOFF.md §2 rule 9). Phase thresholds are in HANDOFF.md §5; change one only with a
  written reason, never to make a test pass.
- Heavy results go to `runs/test_results/`; phase reports are generated by
  `python scripts/render_phase_reports.py` into `docs/PHASE_REPORTS/`.

## Definition of Done (per task)
- [ ] Code matches the charter scope and the task
- [ ] Tests added or updated; `uv run pytest -m light` and `uv run ruff check` pass
- [ ] Measured evidence for any completion claim: command + output + metrics file
  (HANDOFF.md §2 rule 10, report format §6)
- [ ] `bash scripts/verify-charter.sh` passes
- [ ] Formats / interfaces docs updated if behaviour changed
- [ ] Task moved to DONE at commit; handoff written in `/end-session`
